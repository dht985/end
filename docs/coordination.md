## 讨论过程

### 分歧 1：主题方向

- **同学 A**：建议做"城市交通数据分析"，数据容易获取，图表好做。
- **同学 B**：建议做"中国海军建设历程"，主题鲜明，有故事线，但数据需要自行整理。
- **本人**：倾向海军主题——课程要求"个人风格"，军事主题有独特性，且历程+装备天然形成时间线与卡片两类模块，适合练习。

**结论**：采纳海军主题。理由：主题辨识度高，模块间衔接自然（历程→装备→数据→三维），且公开资料足以支撑数据整理。

### 分歧 2：是否纳入三维模块

- **同学 C**：三维模块（A-Frame）调试成本高，浏览器兼容性差，建议作为"可选"不纳入主流程。
- **本人**：课程要求"三维为进阶模块"，纳入可体现整合深度；A-Frame 场景用基本几何体即可，不必追求拟真。

**结论**：纳入三维模块作为进阶模块，但限定"几何船体+标签"的最低可行形态，不做复杂模型加载。

### 分歧 3：数据真实性边界

- **同学 A**：装备参数（排水量、长度）必须精确，否则有误导风险。
- **同学 B**：作为学习原型，部分数据可取约数，但需标注"公开资料整理"。

**结论**：采用约数并统一标注数据来源为"公开资料整理（仅作学习展示）"，在 README 与页脚均注明，避免被误作权威数据。

### 分歧 4：提交策略

- **同学 C**：一次性提交所有代码，省事。
- **本人**：课程要求不少于 7 次提交，应按模块分批提交，便于回溯。

**结论**：按模块拆分提交（骨架/历程/装备/可视化/三维/文档/实施计划），每次提交信息具体，便于审查与回溯。
